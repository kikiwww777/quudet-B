# QuuDet YOLO Lab：从零开始使用指南

本文说明从「什么都没有」到「能训练、验证、检测」的完整路径，按顺序做即可。

---

## 1. 这是什么

**QuuDet YOLO Lab** 是一套围绕 Ultralytics YOLO 的本地/内网实验环境：

| 部分 | 说明 |
|------|------|
| `quudet-yolo-lab/` | 浏览器里的操作界面（仪表盘、数据集、训练、测试、检测、任务等） |
| `quudet-yolo-lab-backend/` | FastAPI 后端：创建任务、写数据库、调 `yolo` 命令行执行训练/验证/预测 |
| `ultralytics-main/` | Ultralytics 源码与配置；界面里的模型 YAML、数据集 YAML 列表由此扫描生成 |
| `docker-compose.yml` | 可选：一键起 API、Worker、PostgreSQL、Redis、Nginx 静态站 |

**默认 `DISABLE_AUTH=true`**：本机/内网使用时一般**不用登录**，前端直接调 API。

---

## 2. 开始前请确认

1. **仓库结构完整**：根目录下同时有 `quudet-yolo-lab`、`quudet-yolo-lab-backend`、`ultralytics-main`（或你已将 `YOLO_WORK_DIR` 指到包含 `ultralytics-main` 的目录）。
2. **Python**：本机开发建议 **Python 3.11+**（与 README 一致）。
3. **GPU（可选）**：有 NVIDIA GPU 时安装对应 CUDA 版 PyTorch，训练/推理会快很多；仅用 CPU 也能跑通小数据试流程。
4. **命令行里有 `yolo`**：安装后端依赖后，Ultralytics 会提供 `yolo` 可执行文件；Worker/API 实际是通过 `yolo train / val / predict` 跑任务。

---

## 3. 方式 A：用 Docker 一键启动（推荐新手）

在**项目根目录**（包含 `docker-compose.yml` 的那一层）执行：

```bash
docker compose up --build
```

首次会构建镜像，稍等片刻。

### 启动成功后访问什么

| 地址 | 用途 |
|------|------|
| http://localhost:8080 | Web 界面（Nginx 托管 `quudet-yolo-lab` 静态文件） |
| http://localhost:8000/docs | Swagger API 文档 |

Compose 里会把**当前工程目录挂载为容器内 `/workspace`**，并设置 `YOLO_WORK_DIR=/workspace`，因此模型/数据路径应写成相对仓库根的路径，例如：

- `ultralytics-main/ultralytics/cfg/models/.../*.yaml`
- `ultralytics-main/ultralytics/cfg/datasets/coco8.yaml`

预训练权重如 `yolov8n.pt` 首次运行时会由 Ultralytics 自动下载（需能访问外网）。

### Docker 模式下后台包含什么

- **api**：FastAPI，端口映射 `8000`
- **worker**：Celery，消费 Redis 队列执行 YOLO 任务
- **db**：PostgreSQL
- **redis**：消息队列
- **web**：静态前端，端口 `8080`

若 8080 页面顶部要填 API 地址：用 **`http://127.0.0.1:8000`**（或你实际映射的后端地址）。若前端与 API 同域代理，也可按界面说明留空或填相对路径（视你的部署而定）。

## 4. 方式 B：Windows 本机开发（不装 Docker）

### 4.1 安装依赖并配置环境变量

```powershell
cd quudet-yolo-lab-backend
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

用编辑器打开 `.env`，按需修改：

- **`YOLO_WORK_DIR`**：若仓库不在默认推断路径，改成你的**项目根目录**绝对路径，例如 `D:/yolo26`（该目录下要有 `ultralytics-main`）。
- **`DISABLE_AUTH=true`**：保持即可免登录。
- **不想装 Redis / Celery**：可设 **`SYNC_JOBS=true`**，任务在 API 进程内同步执行（仅适合本机调试，勿用于多进程生产）。

未设置 `YOLO_WORK_DIR` 时，后端会把「`quudet-yolo-lab-backend` 的上两级目录」当作工作区根（即常见布局下的仓库根）。

### 4.2 启动 API

```powershell
cd quudet-yolo-lab-backend
.\.venv\Scripts\activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 4.3 若使用异步队列（`SYNC_JOBS=false`）

需本机安装并启动 **Redis**，再另开终端：

```powershell
cd quudet-yolo-lab-backend
.\.venv\Scripts\activate
celery -A app.celery_app worker -l info
```

### 4.4 打开前端

任选其一：

- 用浏览器直接打开 **`quudet-yolo-lab/index.html`**（`file://` 时部分浏览器限制跨域，若接口失败请用下面方式）。
- 用 **VS Code Live Server**、或任意静态服务器，把站点根目录指到 `quudet-yolo-lab`，并保证 **CORS**：`.env` 里 `CORS_ORIGINS` 包含你的前端来源（如 `http://127.0.0.1:5500`）。

页面右上角 **API 地址**填：`http://127.0.0.1:8000`，点 **应用**。

## 5. 界面上的推荐操作顺序（业务流程）

下面按「第一次跑通」的顺序说明。

### 步骤 1：确认 API 连通

1. 打开 Web 界面。
2. 右上角 API 填 `http://127.0.0.1:8000`（Docker 用同样逻辑；若你做了反向代理则填实际地址）。
3. 点 **应用**，看仪表盘是否能刷出统计与任务列表（无任务时显示 0 也属正常）。

### 步骤 2：准备数据（二选一或组合）

**选项 A — 使用内置示例**

- 在「数据集管理」里，「数据集配置」下拉里选带 **`[内置]`** 的项（如 `coco8.yaml`），可直接做小规模训练/验证试跑。

**选项 B — 上传自己的数据**

1. 进入 **数据集管理**。
2. 点击 **上传数据集**。
3. 推荐：YOLO 格式 **ZIP**，内含 `images/` 与 `labels/`，并包含或能解析出 **`data.yaml`**（类别名写在 yaml 里）。
4. 上传成功后，同页面的「数据集配置」中会出现 **`[上传 #id]`** 项；训练/测试时选它即可。

### 步骤 3：发起训练

仍在 **数据集管理** 页面下半部分的 **训练配置**：

1. **模型架构 / 规模**：从下拉选择 YAML 与 n/s/m/l/x 等规模。
2. **数据集配置**：选内置或刚上传的数据集。
3. **预训练权重**：可选官方 `.pt`，便于收敛。
4. 填写 **轮次、批次、图像宽高、设备、workers** 等。
5. **优化与正则、数据增强**：已带 Ultralytics 常见默认值，可按需修改。
6. 点击 **开始训练**（或快速开始）。

到 **任务管理** 可查看状态；**训练任务监控** 可看曲线（有 metrics 时）。

### 步骤 4：模型测试（验证）

1. 打开 **模型测试**。
2. 选择 **官方预训练权重** 或 **用户训练权重**（用户权重来自 `runs/` 等扫描结果）。
3. 选择数据集、宽高与 conf/iou 等。
4. **开始测试**。

### 步骤 5：目标检测（单张图/视频）

1. 打开 **目标检测**。
2. 选权重。
3. **选择图片/视频**，再调置信度、IoU、宽高（预测支持矩形 `[高, 宽]`）。
4. **开始检测**，在任务详情或页面底部查看可视化结果（视实现而定）。

## 6. 路径与配置容易踩坑的地方

1. **`ultralytics-main` 必须能被找到**  
   否则 `/api/v1/options/yolo` 拉不到模型/数据集列表，下拉里是空的。

2. **`YOLO_WORK_DIR`**  
   Docker 已设为 `/workspace` 并挂载仓库根；本机若把仓库放在非默认位置，务必在 `.env` 里设置正确的绝对路径。

3. **`SYNC_JOBS=true`**  
   只装 API、不启 Celery 时可用，适合单人本机；生产环境请关闭并使用 Worker + Redis。

4. **开启登录 `DISABLE_AUTH=false`**  
   需自行拿 Token（如 `POST /api/v1/auth/login`），并在请求头带 `Authorization: Bearer ...`。默认管理员见仓库根目录 `README.md`。

5. **训练/验证的图像尺寸**  
   Ultralytics 对 train/val 使用正方形 `imgsz`；界面若宽高不一致，后端会取较大边。检测（predict）可使用矩形。

- [ ] 数据集下拉里能看到 `[内置]` 或上传项。
- [ ] 创建训练任务后，任务状态会从排队变为运行/成功（`SYNC_JOBS` 时界面可能稍慢，看 API 日志）。
- [ ] 本机可执行：`yolo --help`（在已 `activate` 的 venv 中）。

## 9. 多机集群（主控节点 + 工作节点）

当你希望“主控机器统一管理其他算力设备”时，使用中心调度模式：

### 9.1 主控机配置

在 `quudet-yolo-lab-backend/.env` 设置：

```env
CLUSTER_ENABLED=true
NODE_SHARED_TOKEN=replace-with-shared-node-token
NODE_HEARTBEAT_TIMEOUT_SECONDS=20
```

启动主控 API 后，前端会有“节点管理”页面。

### 9.2 工作机（算力节点）启动 agent

每台工作机都要能运行 YOLO（Python 环境 + `yolo` 命令可用），然后执行：

```powershell
cd quudet-yolo-lab-backend
.\.venv\Scripts\activate
$env:MASTER_API_BASE="http://主控机IP:8000"
$env:NODE_ID="node-gpu-01"
$env:NODE_NAME="GPU01"
$env:NODE_TOKEN="replace-with-shared-node-token"
python -m app.agent.runner
```

可选参数：

- `NODE_MAX_CONCURRENCY`：该节点最多并行任务数（默认 `1`）
- `POLL_INTERVAL_SECONDS`：拉取任务间隔（默认 `4`）
- `HEARTBEAT_INTERVAL_SECONDS`：心跳间隔（默认 `5`）

### 9.3 使用方式

1. 打开主控前端的 **节点管理**，确认节点在线。
2. 在训练/测试/检测页面选择“执行节点”（或保持自动）。
3. 创建任务后，任务会分发到对应节点执行。
4. 若任务关联了“已上传数据集（`dataset_id`）”，节点会在执行前自动从主控拉取数据集压缩包并解压到本机缓存目录，再使用本地 `data.yaml` 路径训练。
5. 在任务列表可按节点筛选，监控页可查看远端训练指标与进度。
